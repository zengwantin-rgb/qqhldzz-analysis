# 第十一轮：带玩家归属的能力手牌与推荐目标路径

本轮检查上一轮发现的番型推荐数据是否另有玩家归属字段，并追查独立的玩家能力手牌结构。没有取得新的实时对手牌值来源。

## 结构与归属

扫描全部恢复程序集，得到 [8 个目标结构及 8 个直接引用方法](ownership-paths.json)。8 个结构是下列 4 类结构各自的 protobuf 与 TDR 表示：

| 结构类别 | 显式座位成员 | 已恢复的内容 |
| --- | --- | --- |
| TNewRecommendFanTarget | 无 Seat/Chair 成员 | 推荐目标列表、界面模式 |
| TOneNewRecommendFanTarget | 无 Seat/Chair 成员 | 番型、目标牌、当前手牌与标签等推荐字段 |
| TPlayerTotalHandAbilityTileInfo | 顶层无，座位在子条目 | 玩家能力手牌条目列表 |
| TPlayerHandAbilityTileInfo | SeatID / nSeatID | 座位、条目数量、位置/牌面/牌背条目 |

推荐目标的数量不是玩家数量，目标索引也没有在本轮被解释为座位号。上一轮实际检查点已经证明推荐中的当前手牌与自己一致，本轮没有发现应将这些字段解释成其他三家手牌的证据。

能力手牌结构能够表达带座位的牌条目，但条目可能是部分能力展示、占位或其他数据。字段存在不能证明普通房间下发了完整对手暗牌，位置和牌背字段的具体含义也不能仅凭名字确定。

## 直接引用代码

玩家能力手牌结构的业务直接引用只出现在 Pb2TdrConverter.ConvertTPlayerTotalHandAbilityTileInfo：它把 protobuf 的 SeatID、TileInfos 转成 TDR 的 nSeatID、astTileInfos，并复制位置、牌面、牌背字段。

本轮未找到手牌模型更新或显示代码对该结构的直接读取。这个结果只限定于恢复出的托管程序集及直接字段/方法引用，不排除原生代码、反射、运行时补丁或其他动态访问。

其余 7 个直接引用方法属于推荐数据转换、NextToDo 分发、推荐接收与模型构建、回放重建、变牌事件及比牌事件路径。自动生成的 protobuf 嵌套工厂已排除，避免把构造对象的代码误列为业务显示逻辑。

## 与已有真实对局记录对照

[汇总结果](ownership-summary.json)将恢复的 TLV 枚举常量与先前已验证的同一局日志统计对照：

| TLV 类型 | 恢复的值 | live 阶段记录次数 |
| --- | ---: | ---: |
| EM_DN_TLV_ABILITY_TILE_WALL_INFO | 108 | 2 |
| EM_DN_TLV_PLAYER_HAND_ABILITY_TILE_INFO | 110 | 0 |
| EM_DN_TLV_NEW_RECOMMEND_FAN_TARGET | 168 | 66 |

次数是类型名称在处理日志中的出现次数，可能包含重复循环打印，不是独立网络消息数。玩家能力手牌类型在已记录类型中没有出现；零次记录不能证明所有未写入日志的消息均不存在。

牌墙能力类型虽然出现了 2 次，但此前没有取得它的实际负载，不能还原其条目或将它替代为其他玩家手牌。推荐类型的实际数据已在第十轮定位并验证为自己的推荐/当前手牌路径。
