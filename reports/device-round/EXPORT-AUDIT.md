# 第七轮：复查原有 ZIP 的完整覆盖范围

本轮使用先前提供的同一份加密 ZIP，没有要求重新打一局，也没有新增设备数据。分析代码及合成回归测试在 GitHub Actions 运行；本机仅准备源码并读取脱敏产物。

## 覆盖审计

[文件覆盖结果](export-coverage.json)确认 ZIP CRC 有效，清单声明的 5 个文件全部存在，没有重复条目、清单缺失或额外未声明文件。5 个文件分别为：

| 条目 | 按路径归类 | 大小 | 本轮检查 |
| --- | --- | ---: | --- |
| 1 | record 类 .dat | 16 字节 | 二进制控制字符、零字节统计、已知字段字节搜索 |
| 2 | 云服务日志 | 35,389 字节 | 全文已知字段搜索及嵌入负载探测 |
| 3 | 主游戏日志 | 4,419,584 字节 | 全文已知字段搜索及嵌入负载探测；原有牌局解析继续通过 |
| 4 | 活动日志 | 140,025 字节 | 全文已知字段搜索及嵌入负载探测 |
| 5 | 其他日志 | 3,159 字节 | 全文已知字段搜索及嵌入负载探测 |

条目 1 的路径仅含 record 提示，不含 replay 提示。它有 12 个文本控制字符及 6 个零字节；未命中已知牌值字段。尚未确认其格式与用途，不能称为已经恢复的牌局回放，也不能以字段名搜索为空排除紧凑二进制编码。

主游戏日志严格 UTF-8 解码失败，但容错解码只有 3 个替换字符，仍有 32,375 行且无零字节。审计中的 non_utf8_binary 标签表示严格解码失败，不意味着整份日志加密或无法读取；本轮文本探测明确包含它。

## 已修复的分析覆盖缺口

此前 probe_embedded_payloads.py 只读取第一份 Log398 主日志。本轮改为逐个处理 ZIP 内的文本条目，在结果中记录条目编号；二进制文件不冒充 JSON 文本。

[扩展后的探测结果](embedded-payload-probe.json)确认条目 2、3、4、5 均已扫描，条目 1 未作 JSON 解码。4 份文本中仍未找到已识别的压缩缓冲区、牌墙对象或建议对象，没有新增对手暗牌证据。该探测只针对已知游戏字段，不是任意字符串解密或全部协议解析。

## 清单记录但未装入 ZIP 的文件

扫描清单含 16 个候选文件，实际只导出 5 个。其余 11 个仅有清单元信息，内容不在这个 ZIP 中：

| 类别 | 数量 | 已知大小 |
| --- | ---: | --- |
| 另一份主游戏日志 | 1 | 1,298,432 字节 |
| 云服务日志 | 5 | 60,827、14,197、24,822、109,324、13,663 字节 |
| patch 类 .bytes | 1 | 76,786 字节 |
| 配置或数据 .data | 3 | 6,580、1,092、5,552 字节 |

优先补充的已有文件是另一份主日志、record 类 .data 及 patch 类 .bytes；这只是验证优先级，不代表它们必然包含对手手牌。不需要以新增对局替代这些缺失的旧文件。若原设备已删除它们，单凭清单不能重建其内容。
