## Decoder validation and limitations

Only private copies of recovered assemblies are used in an isolated Mono container with no network, read-only inputs/root, caller UID, dropped capabilities, bounded memory/CPU/processes and a private output mount. IFix Boolean guards are disabled in those private copies so no runtime patches execute; unused optional parameter defaults are removed for metadata compatibility. Original input/phone code is unchanged. No decoded card values, player IDs, raw buffers or exception messages are published. Temporary plaintext is removed by the workflow.

The serializer tables yield 96 message selectors and 203 TLV selectors. Committed ProtocolUnions.cs is checked against original IL, including deal 1→stNotifyDeal and table 8→stTableInfo. Field reading traverses only the selected root/TLV branch, omits null fields and keeps existing traversal/output bounds. A nested-union regression places an oversized array in an unused branch and confirms it is skipped; unknown selectors fail rather than guess.

All 58 stored records produce modeled protocol objects and field JSON with this shared code. That is not a claim of complete or lossless decoding: 57 records consume all bytes; type 160 (stNotifyWinStreakBallSettle), sequence 54 of entry 5, consumes 40 of 48 bytes, leaving 8 unmodeled bytes. Only 39/58 pass exact byte roundtrip. The other 19 are retained as mismatches. A second decode of the regenerated bytes preserves modeled fields for 40/58 (the 39 exact matches plus type 160); the remaining 18 do not pass this check and are not claimed to be lossless; packet interpretation is bounded by this limitation and the private-copy/runtime-patch differences. Root selector 160 is not used as evidence that no other information exists.

## Observed gameplay fields

There are 33 wait-field objects. Every reported extra-command and declared extra-tile count is zero. Nine draw-field objects all report seat 0, consistent with the separate HandleSelfRedraw seat observations; this is self data. Full THandTiles objects occur only in captured Hu notification 50: seats 0/1/2/3 contain 10/7/10/4 nonzero entries respectively, with matching declared counts. This is post-Hu disclosure, not ordinary live opponent visibility. Seat identity is not inferred solely from a hand match.

Nine embedded buffers decode as bounded LZ4 blocks, with exact reported decompressed sizes. All have the known UnitProtoValue field 1. All nested advice, discard/ting candidate, tile and fan message schemas parse with zero unknown tags and zero wire-type mismatches. Only schema/count metadata is published. Successful LZ4 decoding identifies the format of these samples, not every implementation detail of native TSDK Uncompress.

## Deliverable

0.2.2 Beta is built, signed, regression-tested and published. It uses the verified active-branch reader as fallback for TDR serializer failures, to capture the missing deal/table data. The field reader has been validated on existing captured objects in isolation; phone fallback on those missing messages is still unverified. The native HUD is a recorder status label. Live opponent-hand display remains unimplemented and no opponent values are invented.
